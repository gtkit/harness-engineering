# MCP stdio

## 协议流与启动

stdio 通过客户端启动的子进程标准流交互：stdin 读取协议，stdout 输出协议，日志可走 stderr；不得在 stdout 输出非 MCP 内容。具体消息/协商规则按目标版本读取 [stdio 规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio)。

实现与测试同时覆盖：

- 程序入口、SDK 错误日志、依赖初始化、CLI 帮助/诊断、版本输出、panic 恢复和退出错误的去向。
- 子进程 stdout/stderr 分别捕获并有大小上限，不继承 MCP 的 stdout；不能把二进制内容或未转义子进程输出写入协议通道。
- 大消息的有界读取、多个消息连续到达、不完整消息和非法 JSON；消息写入由 SDK 或单一串行机制协调，禁止 goroutine 交错写字节。
- 一般日志优先采用符合输出要求的 gtkit/logger；SDK 要求特定接口时按 `.harness/guides/dependencies.md` 处理，不凭默认 logger 去向做假设。

## 配置与权限

客户端 command/args/env 按实际安装方式验证。用户目录、二进制与外部程序路径由运行时定位或用户提供；项目示例不得出现开发机器路径。

启动目录可能与二进制目录不同，不能依赖 cwd 寻址或默认将 cwd 视为已授权资源。读取权限来自服务端明确配置；客户端传入的路径/roots 仍须验证。

配置缺失、外部 helper 缺失、平台不支持时，按项目契约选择启动失败或工具级明确不可用；不要让客户端一直等待，也不要自动下载并执行来源不明程序。

## 生命周期

- 信号、stdin EOF、协议取消和进程终止分别处理；确认所选 SDK 如何取消/等待在途工作。
- 为请求和进程定义有界退出时间；不让队列、阻塞 pipe 读取、日志推送或外部命令阻止退出。
- 外部程序需要进程树控制时按 OS 实现并验证；停止父进程不一定停止子孙进程。结束后回收 wait、pipe、句柄和临时资源。
- 超时或取消不等于撤销已提交的文件/外部写入。清理可用单独短预算，不复用已经失效的请求 context 盲目重试。

## 验收

通过真实可执行入口，以客户端相同 command/args/env 测试所选协议握手/请求、工具调用、错误、EOF 和退出；捕获 stdout 并确认所有内容都属于合法协议。覆盖 helper 缺失、取消、大输出、重复调用和部分提交。直接调用业务函数不能替代本项。

真实客户端尚未安装或未经授权修改其配置时，记录未验证；禁止为验收自动改客户端配置。二进制分发另见 `.harness/guides/release-and-distribution.md`。
