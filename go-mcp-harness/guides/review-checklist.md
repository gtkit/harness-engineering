# Go MCP 改动审查

按本次 diff 和实际调用链取适用项；本表是人工核对提纲，不是自动运行命令或宣布通过的依据。

- [ ] 方案已落盘并回读，范围、原项目路径和当前阶段一致，已有变更保留。
- [ ] 没有强改目录、增加无收益抽象、无理由替换依赖或引入无需求的服务。
- [ ] Go/SDK/协议/客户端组合明确，所有 API、模块主版本和包名有依据。
- [ ] gtkit 候选按能力评估，日志、JSON、JWT 的协议/安全边界没有被偏好覆盖。
- [ ] 工具名、schema、默认值、错误和结果保持约定；两种传输的业务语义一致。
- [ ] 认证与授权逐次执行；会话/连接/客户端声明不能替代资源权限；跨用户状态隔离。
- [ ] stdio stdout 纯净；HTTP JSON/SSE、Origin、代理和按版本取消行为正确。
- [ ] context、超时、并发、队列、输入/输出大小、下游调用与关闭都有边界。
- [ ] 文件、URL、外部命令与输出处理符合权限；临时资源归属、提交点与重复执行语义明确。
- [ ] 部分成功、结果未知、已提交后清理失败有真实且不诱导误重试的返回。
- [ ] 日志/metrics/产物无秘密、个人用户名或本机真实路径，字段基数有界。
- [ ] 配置、示例、文档与实际读取/回落一致；安装、版本、平台和回滚按影响面核对。
- [ ] 测试证据覆盖受影响最外层入口；mock、进程内、真实客户端/依赖分别报告。
- [ ] 受控质量检查只在功能完成且授权后执行；无未经授权的容器/安装/提交/发布。

有缺陷时先报告可复现问题、影响、位置与依据，避免把风格偏好当 bug。按 `.harness/guides/acceptance-gates.md` 给出限定范围的结论。
