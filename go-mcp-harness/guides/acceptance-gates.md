# Go MCP 交付验收

本指南作为 go-mcp-harness 的验收路由，优先于共享工作流中基于文件扩展名或 Web 项目假设的默认路由。所有检查仍受用户授权约束。

| 当前改动 | 验收范围 |
|---|---|
| 文档、注释、规则说明 | 只回读指定内容，不执行测试或门禁 |
| Go 工具或本地 stdio 行为 | 相关功能、SDK 适配、进程/真实依赖；运行行为按 `backend-acceptance` 中适用条目审视，无 DB/HTTP 的条目标不适用 |
| Streamable HTTP 行为 | 上述适用业务项，加认证、主体隔离、流、取消、资源限额、代理与关闭 |
| Node/安装/打包 | 启动、版本/平台、下载校验、权限、失败恢复；没有浏览器 UI 不加载 `frontend-acceptance` |
| 真实浏览器界面 | 才按影响面加载 `frontend-acceptance`，跨端行为再做联调 |

具体场景见 `.harness/guides/testing-and-validation.md` 和 `.harness/guides/release-and-distribution.md`。规则生成/加载验证不等于对应 MCP 应用已经通过这些场景。

交付报告至少列出：

- 授权范围与实际文件、协议/SDK/平台组合。
- 已完成功能和真实执行的验证命令、退出码、结果。
- 权限、取消、写入提交/清理和依赖集成的证据。
- 未执行、未验证、不适用分别说明；缺少真实客户端证据时限制兼容性结论。
- 是否安装、提交、发布；没有执行不得声称完成。

功能完成后再询问是否运行受控质量检查；未获准的检查保留未执行，不能用默认完成标准强行运行。阶段结束只更新该阶段计划，不自动进入下一阶段。
