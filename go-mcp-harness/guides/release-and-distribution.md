# MCP 安装、分发与回滚

## 先确定交付形态

按项目需求选择 Go 二进制、源码安装、Node 启动器、宿主插件清单或远程 HTTP 地址。无需同时提供全部形态。harness 安装与 MCP 应用安装分别处理；配置文件存在不代表客户端已经加载或调用成功。

## 本地二进制与启动器

- Go MCP 可以通过 npm 分发：区分 Go 服务实现、npm 安装器和 Node launcher。开发/构建环境需要的 Go 工具链不能自动成为最终用户的安装依赖；分发预编译资产时，缺少平台资产应明确报错，不静默改为下载 Go 或本地编译。
- npm 的 `bin` 指向真实随包发布的 launcher；核对 `files`、`engines`、平台资产选择、Windows 命令包装与生产依赖。用户运行 npm/npx 命令不代表正在开发 TS MCP，不添加无关前端框架或完整 TS 服务工具链。
- 若安装依赖 lifecycle script，说明禁用脚本、离线、代理、只读安装目录及无写入权限时的确定行为；启动阶段不得静默下载可执行文件。包装器转发 Go 进程的标准流、信号和退出状态，不重复实现工具业务。
- 明确支持的 OS/CPU、外部程序版本与许可、原生权限、Go 最低版本和 CGO 需求；交叉编译成功不等于目标机可用。
- command/args/env 和工作目录按宿主实际配置格式生成；自动发现/路径含空格/非 ASCII/无执行权限/依赖缺失都要处理。示例使用占位符，无真实本机路径。
- Go 产物使用项目允许的可复现构建方式与路径清理设置；检查二进制、压缩包、错误报告及源码映射是否带开发者目录。
- Node 分发时安装器、launcher、package 清单、Go 版本与 release 资产命名保持一致；launcher 正确传递 stdio、信号和退出码，不在 stdout 输出横幅。
- 下载来源、重定向、签名或校验和及其信任来源明确；同一不可信站点的哈希不能视为独立真实性证明。下载失败或校验不符时不能继续执行。
- 使用临时下载后验证再原子安装；保护旧版本，核实缓存键包含版本与平台，支持并发安装、磁盘满、离线缓存、损坏缓存与更新中断。
- 清理仅删除本次拥有的临时产物；不重写用户数据、授权根或其他客户端配置。

## 宿主清单与远程地址

宿主插件清单、MCP 注册文件、图标与软件包字段按当前宿主官方格式核实。配置的读取位置、相对路径基准、变量展开、敏感字段支持因宿主而异，不能套用另一客户端格式。

HTTP 部署说明明确 URL、TLS/认证、客户端注册方式、支持协议、代理与兼容范围；配置不能携带可公开复用的真实 token。宿主对 OAuth、SSE 和新版协议的支持须分别验证。

## 版本、升级与回滚

协议兼容性、工具契约、客户端配置和安装资产一并评估 SemVer 影响。CHANGELOG、Go 版本常量、package 元数据、资产/tag 一致；未经明确授权不得首次升级/发布为 v2。

升级前确认用户配置及数据保存策略、前后版本互操作、认证/会话/任务在重启后的行为。回滚需能切回已验证资产与匹配配置；涉及持久格式变化时先提供数据兼容和恢复方案。

提交、发布、安装全局程序、修改宿主配置、部署远程服务是独立授权动作。先准备可审阅成果，再按已有授权执行；本指南不提供这些操作的默认许可。
