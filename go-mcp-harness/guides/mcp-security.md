# MCP 权限与外部资源安全

## 信任边界

明确客户端/调用主体 → MCP 服务 → 本地或远程资源的授权链。模型生成的参数、工具描述、客户端 roots、检索内容与下游响应都视作不可信输入；参数合法不等于资源已授权。工具注解不能替代权限检查。

本地工具按明确授权根操作；远程请求按已认证主体授权。共享进程中禁止把最后一次请求的路径、token、租户或配置存为全局默认。缓存、临时产物、任务、订阅、分页游标同样绑定主体和资源范围。

## HTTP 授权

先决定受保护资源的授权服务器、客户端类型、scope 与撤销/过期策略。使用标准 MCP 授权时完整覆盖发现和资源服务器验证，不把一个 JWT 中间件称为完整 OAuth。

令牌需验证目标资源、签发方、有效期与允许算法；上游 API 使用独立授权的 token，不透传客户端给 MCP 的 token。实现客户端授权码流程时，按规范验证 PKCE、重定向和授权服务器绑定；抓取发现/JWKS/元数据同样限制网络目标与大小。[授权安全规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/security-considerations)

`gtkit/gojwt` 可作为已核实的 JWT 能力候选；opaque token 按签发方验证契约处理。拒绝未知 kid 时不得发起无限 JWKS 请求；缓存/轮换、失效和授权故障均有边界。不得把 token、cookie、密码或连接串写入日志/结果/示例。

## 文件与压缩包

- 明确读取、创建、覆盖、删除各自权限。规范化和权限检查必须针对最终操作对象，不能只用字符串前缀判断目录归属。
- 处理相对/绝对路径、`..`、符号链接、硬链接、大小写与平台路径差异；需要抵御 TOCTOU 时使用当前 Go/平台实际支持的根约束或句柄能力，并确认不允许的链接/文件类型。
- 压缩/解压分别限制输入、展开字节、文件数量、单文件大小、路径深度与耗时；条目预检和写入时校验缺一不可。拒绝设备文件、危险链接和越界条目。
- 默认不覆盖已有产物，覆盖须明确授权。临时写入、原子提交和清理具有明确所有者；失败时不得删除其他请求或用户的文件。
- 已提交后清理失败如实报告产物状态；回滚不能重序列化或改写原数据语义。磁盘满、权限不足、取消和关闭失败均属于验收范围。

## 外部命令与网络

- 外部命令使用已核实可执行文件与参数数组，禁止将工具参数拼进 shell。清理环境变量与继承句柄，明确工作目录、超时、输出上限和子进程回收方式。
- 可执行路径来自可信配置/发现过程，不允许调用方随意替换执行程序。程序版本、签名/校验和、平台与许可须核实，不自动下载执行。
- 出站 URL 按业务允许范围校验 scheme、host、端口、DNS/IP、重定向与代理；阻止非授权内网、loopback、link-local 和云元数据目标。需要访问内网的工具采用明确 allowlist，不将所有地址放开。
- 对 HTTP 响应、解压后 body、分页、重试、总时间和并发设限。上游响应里出现的 URL/文件名不能直接成为下一步可信执行目标。

## 安全证据

围绕实际能力测试越权、跨用户数据泄漏、恶意路径/条目、命令参数注入、SSRF 重定向、超大输入、取消与失败清理。真实 OS 权限、客户端确认和上游授权需要实际环境证据；mock 只能证明覆盖到的代码分支。

确认 UI、客户端工具审批与服务端授权是独立边界，不能宣称其中一项替代另一项。测试不得创建项目副本、触达未授权外部资源或泄露真实秘密。
