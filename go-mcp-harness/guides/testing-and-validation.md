# MCP 测试与验证

## 授权边界

按本次功能范围选择必要测试，不因 harness 默认规则扩大任务。纯文档/注释不测试；lint、脚本 lint、vet、modern、全量 race 和覆盖率在功能完成后另行授权。Go 功能测试显式使用 `-vet=off`，避免隐式执行未授权 vet。

测试直接使用原项目代码，不创建项目副本、worktree 或沙箱项目。文件操作所需的合成数据与项目副本不同，但路径/资源使用仍须符合用户约束；先读测试代码，确认不会启动容器、安装工具或触达生产。

## 按影响面选择证据

| 层次 | 必要场景 | 能证明的范围 |
|---|---|---|
| 业务功能 | 正常/边界、缺失与 null、权限、写冲突、失败/取消、重复调用、提交后清理失败 | 受测业务逻辑 |
| MCP 适配 | 真正注册的工具与 schema、参数转换、结构化/文本结果、错误通道 | SDK 到业务的协议适配 |
| stdio 进程 | 实际入口、合法协议输出、错误日志、EOF、信号、子进程回收 | 启动与进程通信 |
| Streamable HTTP | HTTP/JSON/SSE、非法 Origin、鉴权、请求头、不同主体、超大请求、断连、慢客户端与关闭 | 对应版本的 HTTP 传输行为 |
| 真实依赖 | 实际文件系统/helper/授权服务器/数据库/远程 API，按业务选取 | 该环境下的依赖集成 |
| 客户端/分发 | 实际宿主版本、配置、安装入口、架构、升级/回滚 | 实测平台与客户端组合 |

不因纯 Node 启动器就执行浏览器前端验收；不因 HTTP 就测试不存在的数据库。Mock、httptest 和合成输入标注身份，不能代替真实 helper、客户端或 OS 权限验收。

## 传输兼容矩阵

每个声称支持的协议/客户端/传输组合单独记录状态。旧版握手、会话终止、恢复和取消测试只用于对应旧版本；新版覆盖逐请求元数据、头/体一致性、请求流取消等。只支持其中一种版本时明确拒绝不支持的输入，不伪造向下兼容。

同时实现两种传输时，用相同有效/无效业务输入验证 schema、结果和副作用一致；身份来源按模式不同注入。网络认证失败应在工具执行前拒绝，重复写请求不能因重连被自动执行。

## 测试方法

- 优先复用项目现有 fixture、测试入口和 SDK 测试设施；不为可逆的小改动堆砌框架。
- 故障注入覆盖最外层调用，确认返回的提交状态和最终文件/数据一致；不只测试底层 helper。
- 并发使用可控同步事件，避免靠 sleep 猜时序；确认进程/goroutine/流在关闭后停止。需要额外 race 检查时遵循授权边界。
- HTTP 使用 httptest 可验证进程内传输；流式刷新、网关超时和真实认证发现还需经过实际代理/授权链。
- benchmark 使用同环境代表性输入、预热与重复样本，并保留失败样本。性能结论限于测量范围。

## 记录格式

每次写明：功能与协议版本、SDK/Go/客户端/OS 版本、相对命令、数据形状、退出码、结果、失败证据、未执行原因。记录不得带真实本机目录、秘密或用户数据。安装脚本、截图、日志出现预期文字不等于功能已可用。

参考命令仅是形态：`go test -vet=off -count=1 <实际受影响包>`。包路径、build tags、timeout 和运行条件从项目读取；不得把占位符原样执行，也不自动运行全量测试。
