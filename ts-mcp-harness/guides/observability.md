# TypeScript MCP 可观测性

stdio 日志明确输出 stderr，验证 SDK、依赖初始化、npm launcher 和异常路径；协议 logging 与进程日志分别管理，不把 console 输出当 MCP 响应。

按需要记录工具、传输、结果类型、耗时、取消来源、提交状态和经过校验的关联标识。异步请求上下文按运行时能力传播，不能把用户请求 ID 当授权依据。默认不记录完整参数/结果、真实路径、token、cookie 或敏感错误堆栈，脱敏在序列化/落盘前完成。

指标按实际需求覆盖调用失败/取消、延迟、在途/排队/拒绝、流写入错误、下游耗时、事件循环延迟、内存与提交后清理失败。HTTP 200 不代表工具成功；路径、用户和请求 ID 不做无限基数 label。本地小工具不强制引入监控服务器。

容量结论需要真实输入：并发客户端、调用率、P95/P99 目标、消息/输出大小、CPU/内存/磁盘和下游预算。缺失时标待测，不照抄通用 QPS 或内存参数。

性能优化先测基线，按调用链定位事件循环、CPU、GC、原生任务或下游瓶颈，再做最小改变并同环境重复比较。记录输入、运行时/依赖版本、失败和波动，只有可复核收益才保留。诊断产物可能含私有数据/路径，采集和持久化须服从授权与脱敏规则。
