# TypeScript MCP 测试

从真实 package scripts 和现有测试工具选择最小功能范围；先读 pre/post/lifecycle 链，不能借 `npm test` 间接运行未授权 lint、类型检查、覆盖率、安装或服务创建。纯文档/注释不测试；没有 Go 实现，不运行 Go 命令。

| 证据层次 | 验证内容 |
|---|---|
| 业务 | schema 边界、权限、写冲突、部分成功、重复调用、失败/取消及清理 |
| SDK 适配 | 实际注册的工具、参数转换、结构化/文本结果、协议与业务错误通道 |
| stdio | 真实 JS/npm 入口、合法 stdout、stderr、EOF、信号、退出和子任务回收 |
| HTTP | 目标版本的方法/元数据、JSON/SSE、Origin/鉴权、两个权限主体、超限、慢客户端和关闭 |
| 依赖 | 实际文件系统、helper、授权服务器或远程 API；只测本项目实际依赖 |
| 分发/客户端 | 真实 npm 产物、生产依赖、支持的运行时/平台、宿主调用、升级/回滚 |

双传输用同组业务输入核对 schema、结果和副作用，身份来源分别处理。协议/SDK/客户端组合分别记录；不能把进程内 handler 测试说成经过代理或真实宿主兼容。

取消测试确认底层任务停止、监听器/timer/流被释放，不只断言超时响应。使用可控同步点测试竞争、重复关闭与重新挂载，避免靠 sleep 猜时序。mock timer 不能替代真实进程退出证据。

测试直接读取原项目；禁止创建项目副本或用 Docker/安装依赖绕过缺失环境。复用轻量 fixture，不为可逆小改动引入重型框架。未知脚本/包不能通过 npx 自动下载运行。

报告写明相对命令、运行时/SDK/客户端版本、数据形状、退出码、实际结果和未验证项。类型检查只证明静态类型，构建只证明产物生成，npm 安装只证明安装路径，均不能代替功能和协议验收。
