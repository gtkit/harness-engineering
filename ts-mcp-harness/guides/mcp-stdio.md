# TypeScript MCP stdio

[stdio 规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio)要求标准流承载协议。stdout 只输出 MCP 消息；应用日志、`console.log`、调试信息、依赖初始化和启动横幅不得混入。通过 npm/npx 启动时核对整个进程链，不仅直接执行入口。

## 启动与消息

- 使用 SDK 读取/编码消息，输入限制覆盖大消息、非法 JSON、不完整帧和连续消息；异步响应不能交错写字节。
- 明确 `bin`、编译产物、解释器、参数、env 与 cwd；从任意工作目录启动时都能定位包内资源。cwd 不是自动授权根。
- 子进程 stdout/stderr 分别管理并设大小上限，不继承 MCP stdout。诊断和启动失败进入 stderr，并产生确定退出状态。
- 配置/依赖缺失、权限不足、版本或平台不支持时明确失败，不让客户端无限等待，不静默下载程序。

## 生命周期

区分 EOF、信号、协议取消和进程退出。请求取消经 SDK 接入支持取消的 API，明确每个 timer、监听器、异步任务和子进程的清理归属。停止接收新工作后，在总预算内取消/等待在途工作，回收 pipe 和子进程。

不能通过 `Promise.race` 返回超时后遗留后台写操作，也不能依靠终止父进程自动清理整个进程树。取消发生在提交后时如实报告资源状态；收尾使用独立有界预算。

## 验收

以真实发布入口和客户端 command/args/env 验证所选版本的协议初始化/请求、工具成功/失败、EOF、信号、大输出及重复关闭。分别记录直接 JS 入口、npm bin 与真实客户端证据；未运行的路径不标通过。检查 stdout 全部为合法协议，并核实退出后无未管理任务。
