# TypeScript MCP 契约

记录 SDK 精确版本、MCP 协议版本、传输、客户端和能力组合。只声明已经实现并验证的能力；不混合不同 SDK 代际或协议版本的握手/元数据行为。

## 工具、资源和 prompts

- 固定工具名称、描述、schema、默认/可选值、结果结构及错误通道；改字段前核对已有客户端调用。
- SDK 注册的真实 schema 与运行时校验一致，明确未知字段处理、字符串/集合长度、嵌套、数字范围和输出大小。TS 类型不能替代校验，不能靠隐式类型转换改变原契约。
- 区分缺失、null、空值；JSON 输出明确 BigInt、非有限数字、二进制和日期表示，避免暴露 Error 的堆栈/内部路径。
- 资源 URI、模板和分页游标有规范化、访问范围、大小/数量与稳定性约束；不能把 URI 变为任意文件或网络访问。
- prompt 参数和模板边界清楚；工具返回、资源内容、外部网页及客户端数据不能提升为系统指令。
- 工具注解如只读/破坏性仅供客户端理解，不是服务端授权；声明与真实副作用一致。

## 失败、幂等与提交

认证/HTTP 拒绝、JSON-RPC 协议错误、工具业务失败通过对应版本规定的通道返回。HTTP 200、Promise resolved 或返回文本不等于工具成功。

定义执行前拒绝、未提交失败、已提交后清理失败、结果未知的对外含义。错误不能泄露凭据，但应足以判断是否可重试；保留可观察的原始原因。JSON-RPC ID 不等于业务幂等 key；需要幂等时绑定主体、工具和输入，限制有效期。

超时、断连、重连不能自动重放写操作。修改/删除明确覆盖权限、提交点及失败恢复；外层返回与最终资源状态一致。

## 协议兼容

[传输规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports)按版本定义元数据和取消行为。旧版握手/能力协商、会话、恢复与新版逐请求模型分别处理。logging、progress、roots、sampling、elicitation、任务和订阅仅在所选版本/客户端支持且确有需求时启用，并限制权限、数量与生命周期。
