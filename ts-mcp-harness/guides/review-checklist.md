# TypeScript MCP 审查

只审查获准范围，先读计划、错误记录与实际 diff。按风险输出有证据的发现，不凭清单要求添加不存在的功能。

- 运行时/SDK/协议/客户端版本是否明确；模块导出、schema 与发布入口是否兼容？
- TS 类型与运行时校验是否一致；缺失/null、大整数、未知字段与输出大小是否明确？
- stdio 所有路径是否保持 stdout 纯净；npm 包与直接 JS 的进程链是否分别验证？
- HTTP 的 Origin、每请求认证、主体/资源隔离、流、取消与代理是否按目标版本实现？
- 写操作提交点、结果未知、幂等与清理失败是否能避免错误重放？
- AbortSignal 是否真正停止底层工作；监听器/timer/流/子进程是否有界回收、重复清理安全？
- 事件循环、Promise 并发、队列、缓存、消息、外部输出和重试是否有上限？
- 文件/链接、参数注入、SSRF、原型污染与凭据泄露是否有实际能力对应的防护？
- npm 产物、运行时依赖、bin/ESM/CJS、安装脚本与用户配置边界是否明确？
- 是否意外引入 Go、无关前端、数据层或过度抽象？是否保持原目录与接口？
- 配置、文档和测试证据是否同步，是否把静态检查/内存测试扩大成真实兼容结论？

验收按 `.harness/guides/acceptance-gates.md`；审查请求不自动授权修复、安装或质量门禁。
