# harness 与 Loop 架构的关系

这篇文档解决一个常见误解：**Loop 架构里那些能力，哪些是 harness 提供的、哪些是运行时（Claude Code / Codex）提供的。**

本项目提供**项目规则、工作流 skills 和本地执行工具**，不替代编码代理的执行引擎。规则与指南负责约束；已安装的 hooks、错误记忆脚本负责其各自覆盖的操作；组合使用的 openspec-auto 提供会话状态、计划读取、文件范围和检查证据管理。三者是否实际生效，须分别核对加载、启用、信任与真实执行证据。

---

## 能力分工

| 模块 | 谁实现 | 当前分工与边界 |
|-----|-------|-------------|
| **目标与迭代纪律** | 项目规则、工作流工具与运行端 | 规则规定如何推进与停止；工具校验覆盖的状态；执行权限仍以用户授权和运行端为准 |
| **Skills 与领域知识** | 本仓库与独立 skills 内容源 | 本仓库维护六个工作流 skill；各场景包提供入口与指南；领域知识按需引用，不重复维护 |
| **错误记忆** | 本地文件、脚本与 SessionStart hook | 已有 `.harness/error-journal.md` 和未关闭错误摘要；不等于自动学习、跨项目记忆或经验真实性保证 |
| **计划、范围与检查证据** | openspec-auto 组合层 | 已有会话和请求版本、读取记录、文件清单、检查授权及完成态管理；不能视作不可绕过的宿主安全边界 |
| **工具执行与调度** | 实际运行端 | 可用工具、调度接口和生命周期随运行端变化，按当前环境核实；不在说明中永久断言某客户端有或没有某能力 |
| **插件与连接器** | 实际运行端和外部服务 | 仅在当前任务需要时使用已授权能力；诊断不等于安装、启用或访问授权 |
| **独立子代理** | 支持该能力的运行端 | 工作流 skill 不等于独立进程；真实独立审查还需核对上下文隔离、只读限制和当前授权 |

任何项目的开发、审查与验证均在用户指定的真实原目录进行。禁止创建或使用 worktree、临时 clone、分离 checkout 或其他项目副本；并行与测试隔离不构成例外。

## 为什么不另建执行引擎

不是做不到包一层，而是**刻意不做**，理由：

1. **复用当前运行端**。有适用且获准的原生能力时直接使用；没有时报告缺口，不凭技能名称宣称具备。
2. **维持职责分工**。项目约定归 harness，规格与执行状态归 openspec-auto，领域方法归 skills；调度、模型调用与工具权限归运行端。
3. **保持实现简洁**。仅为当前确定需求补工具，不因外部项目功能更多而新增后台调度、记忆服务或重复的执行状态机。

## 各角色分工

- **递归目标（中心）**：harness 给纪律，运行时给执行力。
  - harness 侧：见各模块 `CLAUDE.md` / `AGENTS.md` 的「可验证目标（Goal-Driven Execution）」与「迭代与停止纪律（Verify–Correct Loop）」——先观察再改、在已授权范围内验证、自纠达到规定上界后停手汇报；错误记忆的写入仍须符合当前任务范围。
  - 运行端侧：按当前可用且已授权的工具推进任务；循环能力不豁免停止指令、阶段限制或检查授权。
- **Skills**：本仓库维护工作流入口，独立 skills 仓库维护领域知识；在各自内容源修改，获准后分发。
- **错误记忆**：`.harness/error-journal.md` 提供跨会话记录，guides 提供项目约定；二者都不能代替当前事实核对。
- **规格与执行状态**：组合中的 openspec-auto 管理覆盖范围内的流程，不将所有约束都寄托于提示词。
- **调度 / 连接器 / 子代理**：由实际运行端提供；按需核实，不默认启动、安装或更改权限。

## 实践指引

- 想让 AI 持续推进任务：先明确需求、计划、阶段和可验证完成标准，再使用当前运行端已获准的执行能力；不以“会循环”保证任务正确。
- 想沉淀经验、不让模型重复犯错：靠 `.harness/error-journal.md`（Memory），这是 harness 的强项。
- 想固化团队意图、统一规范：维护入口规则、工作流 skill 与 guides，获准后通过现有安全更新机制分发；内容源更新不等于已有项目已经更新。
- 日常开发按当前规则与技能清单读取相关内容；复杂任务、新会话或切换阶段不自动触发 doctor。
- 纯解释和文档请求不恢复代码任务、不启动 OpenSpec 或测试。lint、vet、modern、全量 race 与覆盖率在功能完成后另行取得授权。
- 安装文件、运行端发现、实际加载、原生回调和验收通过是不同事实，分别报告；不以技能文字或历史记录代替当前执行证据。
